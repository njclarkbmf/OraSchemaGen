# ADR-007: Sequence vs Identity Column Strategy

**Status:** Accepted
**Date:** 2026-04-06
**Context:** OraSchemaGen - Oracle Schema Generator

## Context

Oracle 12c introduced **IDENTITY columns**, which provide auto-incrementing primary key values similar to MySQL's `AUTO_INCREMENT` or PostgreSQL's `SERIAL`. Before 12c, the standard pattern was an explicit `CREATE SEQUENCE` combined with `SEQUENCE.NEXTVAL` in INSERT statements or triggers.

IDENTITY columns are essentially a syntactic sugar over sequences -- Oracle creates a hidden sequence behind the scenes. However, the two approaches have different characteristics:

- IDENTITY columns hide the sequence, making it less accessible for application code
- Explicit sequences give developers direct control over `NEXTVAL` and `CURRVAL`
- IDENTITY columns are not available in Oracle 11g
- The sequence pattern is universally understood by Oracle developers

## Decision

Use **explicit `CREATE SEQUENCE` + `SEQUENCE.NEXTVAL` pattern** rather than Oracle 12c IDENTITY columns for all auto-incrementing primary keys.

Generated pattern:
```sql
CREATE SEQUENCE employees_seq START WITH 1 INCREMENT BY 1 NOCACHE NOCYCLE;

INSERT INTO employees (employee_id, name)
VALUES (employees_seq.NEXTVAL, 'John Doe');
```

Not:
```sql
CREATE TABLE employees (
    employee_id NUMBER GENERATED ALWAYS AS IDENTITY,
    name VARCHAR2(100)
);
```

## Consequences

### Positive
- **Backward compatible with Oracle 11g**: sequences work on all Oracle versions
- **Explicit control**: developers can query `CURRVAL`, pre-allocate values, or adjust sequences
- **Familiar pattern**: universally understood by Oracle developers and DBAs
- **Works across all supported versions**: 11g, 12c, 19c, 21c, 23c
- **Easier to migrate**: other databases use similar sequence patterns
- **Sequences can be shared** across multiple tables if needed
- **Visible in data dictionary**: easier to audit and manage

### Negative
- More verbose than IDENTITY column syntax
- Requires managing sequence lifecycle (drop when table is dropped)
- Slightly more boilerplate in INSERT statements
- IDENTITY columns provide slightly better encapsulation

## Alternatives Considered

### Oracle 12c IDENTITY columns
**Rejected.** While cleaner syntactically, they are not available in Oracle 11g, hide the underlying sequence, and are less familiar to developers coming from earlier Oracle versions. The sequence pattern is more portable and explicit.

### Trigger-based auto-increment (BEFORE INSERT trigger)
**Rejected.** The trigger pattern (`BEFORE INSERT ... BEGIN SELECT seq.NEXTVAL INTO :NEW.id FROM DUAL; END;`) was the Oracle 11g standard but adds complexity. Using `SEQUENCE.NEXTVAL` directly in INSERT statements (ADR-003 ordering) is simpler and more transparent. Triggers are still generated for other purposes (audit, history).

### Default value with sequence (Oracle 12c: `DEFAULT seq.NEXTVAL`)
**Partially considered.** The `DEFAULT seq.NEXTVAL` syntax (12c+) is a good middle ground but still requires 12c+. The explicit `SEQUENCE.NEXTVAL` in INSERT statements (generated by the data generator) is more universally compatible and makes the sequence usage visible in the DML.
